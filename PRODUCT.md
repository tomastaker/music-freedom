# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Bun + TypeScript + React. Приложение собирается в один исполняемый файл на платформу (`bun build --compile`) и открывает интерфейс во вкладке браузера на `http://127.0.0.1`. Отдельного окна (Electron, pywebview) нет. Сборка под Windows, macOS и Linux выполняется с одной машины.

## Users

Человек без технических навыков, который слушает и Яндекс Музыку, и Spotify. Чаще на Windows, реже на macOS, иногда на Linux. Скачивает zip из GitHub Releases, распаковывает и запускает один файл. С консолью, токенами и скриптами не работает.

## Product Purpose

Перенести избранные треки между Яндекс Музыкой и Spotify и поддерживать их одинаковыми.

- Однократный перенос в любую сторону. Треки, которые уже есть в целевом сервисе, пропускаются.
- Кнопка «Синхронизировать»: недостающее подтягивается в обе стороны.
- Удаления не переносятся. Программа ничего не удаляет из библиотек, кроме отмены собственного последнего переноса.
- Перед записью всегда предпросмотр. После записи отчёт и отмена последнего переноса.

Успех: пользователь сам подключил оба сервиса, увидел, что именно добавится, и получил одинаковое избранное без дублей.

## Positioning

Бесплатно и с открытым кодом. Работает на компьютере пользователя: токены и библиотека никуда не уходят. Soundiiz и TuneMyMusic хранят доступ к аккаунтам на своих серверах, а синхронизацию дают только платно.

## Operating Context

- Spotify работает только через приложение разработчика, которое пользователь создаёт сам в Spotify Developer Dashboard. Владельцу приложения нужен Premium. Redirect URI строго `http://127.0.0.1:47813/callback`. Это самый трудный шаг для пользователя, мастер должен провести его за руку.
- Вход в Яндекс по коду подтверждения на `ya.ru/device`, токен вручную не копируется.
- Пользователи из России обычно включают VPN для Spotify. С VPN Яндекс работает, если ходить к нему по IPv4.
- Первый перенос большой библиотеки занимает минуты: поиск в Spotify возвращает максимум 10 результатов за запрос, есть лимиты запросов. Процесс должен переживать обрыв и продолжаться.
- Неофициальный API Яндекса может сломаться. Ошибки сервисов показываются понятным языком.

## Capabilities and Constraints

- v1: только избранные треки («Мне нравится» в Яндексе, Liked Songs в Spotify). Плейлисты, альбомы и исполнители позже. Плейлист с тем же названием в будущем дополняется, а не дублируется.
- Сопоставление: ISRC (у Яндекса его нет), затем исполнитель, название с учётом транслита и версий, длительность. Уровни: точно, под вопросом (пользователь подтверждает), не найдено.
- Архитектура под подключаемые сервисы: позже Apple Music, возможно Deezer.
- Языки интерфейса: английский (основной для публичного репозитория) и русский, с переключателем. README на двух языках, английский основной.
- Приложение не подписано: в README инструкция, как пройти SmartScreen и Gatekeeper.

## Brand Commitments

- Название: music-freedom.
- К пользователю обращаемся на «вы».

## Evidence on Hand

Реальных отзывов, пользователей и метрик нет, выдумывать их нельзя. Есть результаты проверки на одном живом аккаунте (757 лайков в Яндексе, 270 в Spotify): из 20 треков Яндекса в Spotify нашлись 19, из 20 треков Spotify в Яндексе 15, все 5 промахов — пробелы каталога.

## Product Principles

1. Ничего не записывать без предпросмотра. Любое изменение библиотеки видно заранее и отменяемо.
2. Не просить у пользователя технических действий, которые программа может сделать сама. Если без них нельзя (Spotify Dashboard), вести по шагам с проверкой результата.
3. Честно показывать, что не нашлось и почему, а не прятать промахи.
4. Данные пользователя не покидают его компьютер.
